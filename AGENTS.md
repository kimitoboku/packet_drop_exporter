# packet_drop_exporter Development Notes

## General Principles

- The source of truth for implementation is `docs/implementation-plan.md`. Do not create parallel implementation plans; append progress and verification results to the existing document.
- The target is Linux BTF with drop-reason-aware `tp_btf/kfree_skb`; do not determine support from kernel version numbers alone.
- Do not expose packet payloads, IP addresses, ports, PIDs, cgroups, or raw kernel addresses in normal metrics.
- BPF maps use per-CPU counters, and Prometheus scrapes must read an immutable snapshot rather than walking maps directly.

## Linux/Docker Development Environment

- macOS cannot generate or attach BPF bytecode directly, so use a Debian container with clang and libbpf as the baseline environment.
- `docker compose run --rm test` runs BPF generation, unit tests, and race tests.
- `docker compose --profile integration up --build exporter` is a privileged smoke test that uses the Linux host's BTF, kallsyms, and network namespace. Success on the Docker Desktop VM is not a substitute for testing the target Linux host.
- Real-kernel testing requires `CAP_BPF`, `CAP_PERFMON`, `CAP_SYS_ADMIN`/`CAP_SYSLOG` when necessary, and an equivalent of `LimitMEMLOCK`.
- `internal/bpf/drop_bpfel.go` and `drop_bpfeb.go` are regenerated by `go generate ./internal/bpf`; do not edit them manually.
- `drop.bpf.c` has `//go:build ignore` so it is not included in the Go package build; clang receives it only through the explicit `go:generate` directive in `generate.go`.
- In the target kernel BTF, `struct net_device.nd_net` is represented as `possible_net_t`. When changing the interface dimension, always compare the local CO-RE view with the running BTF types.
- Bytecode and Go wrappers generated on Linux are covered by `.gitignore`; Docker rebuilds them with `go generate` every time.
- The symbol resolver publishes complete tables atomically. Refresh it when `/proc/modules` changes, retain the previous table after a refresh failure, and retry while symbolization is unavailable.
- Re-evaluate `ebpf.PossibleCPU()` before each per-CPU map read so CPU-topology changes cannot leave value slices stale.

## Verification

- After implementation, run at least `go test ./...`, `go test -race ./...`, `go vet ./...`, and `git diff --check`.
- Treat attachment of `tp_btf/kfree_skb`, drop-reason resolution, and symbol resolution as complete only after a privileged Linux smoke test. Do not claim real-kernel behavior based only on successful macOS unit tests.
- Map-full conditions, unavailable kallsyms, unknown reasons, and `skb->dev == NULL` must remain observable as failure modes.
- If the host loopback on Docker Desktop cannot reach a host-network container port, use a probe container in the same network namespace, for example `docker run --network container:packet_drop_exporter-exporter-1 curlimages/curl:8.10.1 ...`. On native Linux, use the normal `curl 127.0.0.1:9435`.
- `make docker-integration-test` runs privileged map-full and unavailable-kallsyms checks. `make docker-soak` runs for 24 hours by default; a short verification may override `SOAK_SECONDS` but must not be described as 24-hour evidence.
- Validate the Grafana JSON with `jq`, Prometheus rules with `promtool check rules`, and `.goreleaser.yaml` with `goreleaser check` after modifying release or monitoring assets.

## Documentation and Collaboration

- Repository documentation is written in English.
- Developer discussions may use each contributor's preferred language. Record durable technical decisions, contracts, and verification results in English in the repository documentation.
- Public claims in `README.md` must match evidence recorded in `docs/verification.md`; keep unverified kernel matrices, soak duration, release publication, and performance claims explicitly bounded.
- The project is licensed under MIT. New source and documentation contributions must be compatible with `LICENSE` and must not introduce copied material with incompatible terms.
- Treat issues, pull requests, logs, and test fixtures as public. Do not include packet payloads, credentials, private host data, or raw kernel addresses.
- Keep `CONTRIBUTING.md`, `SECURITY.md`, community templates, release archives, and README links synchronized when the public contribution or release process changes.
- Run `make licenses` after changing runtime dependencies. Release archives must include `THIRD_PARTY_NOTICES.md` and the generated `third_party_licenses/` bundle.
